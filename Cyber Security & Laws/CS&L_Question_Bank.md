### 3.1 Repeated 4 Times (Must Solve)

#### Question 10M-01: SQL Injection (SQLi) Steps, Bypass, and Countermeasures
- **Exam Appearances**: 13/06/2025 (Q.3a), 25/11/2024 (Q.4a), 03/01/2024 (Q.5a), 19/12/2022 (Q.6a)
- **Verbatim Question**: "Explain steps for SQL Injection attack. How to prevent SQL Injection attacks? / State different countermeasures to prevent the attack. (10)"

**Simple 4-Step Attack Explanation:**
1. **Identification**: Attacker inputs special characters (like `'` or `"` or `OR 1=1`) in a web form input box.
2. **Analysis**: Attacker observes database error messages or behavior changes indicating dynamic string concatenation.
3. **Exploitation**: Attacker injects malicious SQL syntax (e.g. `' OR '1'='1' --`) to bypass authentication or extract sensitive tables.
4. **Data Exfiltration**: Attacker runs `UNION SELECT` queries to dump password hashes and credit card records.

**Countermeasures**: Use Prepared Statements (Parameterized Queries), input validation with allow-lists, and principle of least privilege on database user accounts.

### 4.2 HIPAA and SOX Compliance Made Simple

#### HIPAA (Health Insurance Portability and Accountability Act)
Protects Patient Health Information (PHI). Mandates 3 Safeguards:
1. **Administrative Safeguards**: Security policies, employee background checks, security awareness training.
2. **Physical Safeguards**: Facility door badge locks, secure disposal of hard drives containing medical records.
3. **Technical Safeguards**: AES-256 data encryption at rest and in transit, multi-factor login, immutable audit access logs.

#### SOX (Sarbanes-Oxley Act)
Protects investors from corporate accounting fraud.
- **Section 302**: Corporate executives must personally certify that financial records and IT internal controls are accurate.
- **Section 404**: Requires annual third-party independent audits of the company's internal IT systems and controls.

### 4.3 How Buffer Overflow Works and How to Prevent It

**What happens in memory?**
When a program writes more data to a fixed-size buffer than it can hold, the extra data overflows into adjacent memory on the stack:

```text
Low Memory                                                               High Memory
[ Local Buffer (e.g. 64 bytes) ] -> [ Saved Frame Pointer (EBP) ] -> [ Return Address (EIP) ]
---------------------------------------------------------------------------------------------
              Attacker sends 80 bytes of input containing Shellcode:
[ NOP Sled + Malicious Shellcode ] --------------------------------> [ Overwritten Return Addr ]
```

When the function finishes, the CPU jumps to the overwritten Return Address, executing the attacker's shellcode with elevated privileges.

**4 Defense Methods:**
1. **ASLR (Address Space Layout Randomization)**: Randomizes stack and library memory addresses at program launch so attackers cannot predict target return addresses.
2. **Stack Canaries**: Places a secret random integer before the return address. If the canary is modified when the function returns, the program immediately halts.
3. **DEP / NX Bit (Data Execution Prevention)**: Marks stack memory as non-executable so injected shellcode cannot run.
4. **Use Safe String APIs**: Replace dangerous C functions (`gets`, `strcpy`, `sprintf`) with bounded equivalents (`fgets`, `strncpy`, `snprintf`).

### 4.4 How SQL Injection Works and Prepared Statements Defense

**Vulnerable Dynamic Query:**
```sql
SELECT * FROM users WHERE username = 'admin' AND password = '' OR '1'='1';
```
Because `'1'='1'` is always true, the database returns all user records, letting the attacker log in without a password.

**Safe Parameterized Query (Prepared Statement in Java):**
```java
String sql = "SELECT * FROM users WHERE username = ? AND password = ?";
PreparedStatement pstmt = conn.prepareStatement(sql);
pstmt.setString(1, inputUsername);
pstmt.setString(2, inputPassword);
ResultSet rs = pstmt.executeQuery();
```
*Why this is safe:* The database engine treats `?` strictly as literal string values, never as executable SQL code.
