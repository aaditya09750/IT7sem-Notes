- **Exam Appearances**: 04/06/2025 (Q.1a), NOV 2024 / 2025 (Q.1a), plus 2 times in 10M
- **Verbatim Question**: "Define Smart Object in IoT and its characteristics in brief. (5)"

**4 Essential Characteristics of a Smart Object:**
1. **Sensory / Actuation Ability**: Can measure physical phenomena (temperature, light) and act on the environment (switch on motor).
2. **Processing Unit**: Microcontroller (e.g. ESP32, ARM Cortex) for local edge data processing.
3. **Communication Transceiver**: Wireless connectivity (Wi-Fi, BLE, Zigbee, LoRa) to transmit data.
4. **Power Source**: Battery or energy-harvesting unit with power management firmware.

#### Question 10M-01: MQTT (Message Queuing Telemetry Transport) Architecture and QoS
- **Exam Appearances**: 04/06/2025 (Q.3a), 14/11/2024 (Q.4b), NOV 2024 / 2025 (Q.4b), JUNE 2024 (Q.5a), 28-DEC-2023 (Q.5a), 16/06/2023 (Q.6a)
- **Verbatim Question**: "Draw and explain Architecture of MQTT with diagram. List its advantages and 2 advantages over CoAP. (10)"

**Key Concepts to Write in Exam:**
- **Publish / Subscribe Model**: Publishers (Sensors) send data to a Central Broker under a Topic (e.g. `factory/zone1/temp`). Subscribers receive only topics they subscribe to.
- **Lightweight Header**: Minimum fixed header size of just 2 bytes, saving battery and network bandwidth.
- **3 Quality of Service (QoS) Levels**:
  - **QoS 0 (At most once)**: Fire-and-forget; no acknowledgment.
  - **QoS 1 (At least once)**: Sender resends until `PUBACK` is received (duplicate messages possible).
  - **QoS 2 (Exactly once)**: 4-way handshake (`PUBLISH` -> `PUBREC` -> `PUBREL` -> `PUBCOMP`) ensuring zero duplicates.
- **Last Will and Testament (LWT)**: Broker automatically publishes a predefined message if a sensor abruptly disconnects.

## 4. Section 3: Protocol Architectures and System Design Blueprints

### 4.1 MQTT Protocol Architecture and QoS Handshakes

**Pub/Sub Topology:**
```text
[ Temperature Sensor (Publisher) ] ---> PUBLISH ("factory/temp", 28C) ---> [ Central MQTT Broker ]
                                                                                   |
[ Mobile Dashboard (Subscriber) ] <---- FORWARD ("factory/temp", 28C) <------------+
```

**QoS Handshake Steps:**
- **QoS 0**: `PUBLISH` (No ACK from Broker).
- **QoS 1**: `PUBLISH` -> `PUBACK` (Acknowledged delivery).
- **QoS 2 (4-Step Handshake)**:
  1. Publisher sends `PUBLISH`.
  2. Broker receives and sends `PUBREC` (Publish Received).
  3. Publisher sends `PUBREL` (Publish Release).
  4. Broker responds with `PUBCOMP` (Publish Complete).

### 4.2 CoAP Protocol Architecture over UDP

CoAP provides a lightweight RESTful interface over UDP:

```text
Client (Sensor)                                                    Server / Gateway
   |                                                                      |
   +---------- Confirmable (CON) [MID: 0x01, GET /temperature] --------->+
   |                                                                      |
   +<--------- Acknowledgment (ACK) [MID: 0x01, 2.05 Content: "25C"] -----+
   |                                                                      |
   +---------- Non-Confirmable (NON) [MID: 0x02, POST /log] ------------->+ (No ACK needed)
```

**4 Message Types:**
1. **CON (Confirmable)**: Requires an immediate ACK response with matched Message ID (MID).
2. **NON (Non-Confirmable)**: Fire-and-forget telemetry packet.
3. **ACK (Acknowledgment)**: Confirms receipt of a CON message.
4. **RST (Reset)**: Indicates that a message was received but could not be processed.

### 4.3 LoRaWAN 4-Tier Topology and Device Classes

```text
[ End Devices (Sensors) ] --(LoRa RF Chirp Spread Spectrum)--> [ Gateways ] --(IP / 4G)--> [ Network Server ] --> [ Application Server ]
```

**3 Device Classes Comparison Table:**

| Class | Power Consumption | Downlink Latency | Communication Behavior | Best Use Case |
| :--- | :--- | :--- | :--- | :--- |
| **Class A** | Ultra-Low (5-10 yr battery) | High (Only after uplink) | Opens 2 short receive (RX) windows only after transmitting an uplink. | Soil moisture, water meters. |
| **Class B** | Low | Medium | Opens scheduled receive windows synchronized with Gateway time beacons. | Smart street lights, asset tracking. |
| **Class C** | High (Mains powered) | Zero Latency | Constantly keeps receiver listening (except during uplink transmission). | Smart power grid switches. |
